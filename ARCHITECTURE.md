# ARCHITECTURE & ENGINEERING MANIFESTO — `rudolfzinovev.me`

Этот документ фиксирует неизменяемые архитектурные и продуктовые принципы репозитория **rudolfzinovev.me**. Любые последующие коммиты, PR и доработки обязаны строго им следовать.

---

## 1. Rust-First & Крайний минимум JS/TS (Hard Rule)

1. **Язык проекта — Rust.**
   - Весь HTTP-сервер, маршрутизация, рендеринг HTML (SSR), компиляция Markdown, работа с БД (SQLite), криптография/аутентификация, RSS, сжатие (gzip) и кэширование реализованы **исключительно на Rust**.
2. **Запрет на JS/TS-экосистему на клиенте и в сборке:**
   - Никаких `package.json`, `node_modules`, Webpack, Vite, Rollup, Babel, Tailwind CLI на клиенте.
   - Никаких SPA/гидратации (React, Next.js, Vue, Svelte, Astro, HTMX-зависимостей из CDN).
3. **Политика «Крайний минимум JS» (`<= 2 KB` сжатого vanilla JS, Progressive Enhancement):**
   - **100% функционала сайта** (чтение статей, фильтрация по тегам, поиск, переключение языка `RU/EN`, переключение темы `OBSIDIAN / PAPER`, вход в личный кабинет, создание/редактирование/удаление статей и настроек профиля) **обязано работать вообще без JavaScript** (через чистый серверный HTML, HTTP POST/GET, формы и cookies).
   - Единственный клиентский файл `assets/app.js` подключается с атрибутом `defer`, не имеет внешних зависимостей и отвечает **только за микро-улучшения UX**:
     - мгновенное переключение цветовой схемы на клиенте с синхронизацией cookie (`rz_theme`);
     - хоткеи терминальной навигации (`/`, `g h`, `g a`, `g c`) и копирование блоков кода в один клик;
     - живой предпросмотр и подсчёт символов в редакторе статей владельца + защита от случайного закрытия несохранённого черновика.

## 2. Производительность при загрузке (Zero-Bloat Optimization)

Цель сайта — мгновенный First Contentful Paint (суб-миллисекундный ответ сервера, первый экран в пределах одного TCP initial congestion window ~14 KB):

- **Single Self-Contained Binary:** статика (`assets/style.css`, `assets/app.js`, SVG favicon) вшита в бинарник через `include_str!` на этапе компиляции. На диске VPS лежит **один исполняемый файл** и файл базы данных SQLite.
- **Встроенное Gzip-сжатие и версионирование статики:** любой `text/*` ответ (включая HTML и CSS) сжимается на лету через `libz` (`deflateInit2_`, уровень 6) при `Accept-Encoding: gzip`. Статика отдаётся с `Cache-Control: public, max-age=31536000, immutable` и ETag по SHA-256 содержимого.
- **Байт-стабильный HTML:** страница не содержит меняющихся счётчиков. Время рендера уходит в заголовок `Server-Timing` и в микро-скрипт, CSP задаётся хешем скрипта (`script-src 'sha256-…'`) вместо nonce. Поэтому `ETag` + `If-None-Match` реально дают `304` без тела.
- **Нулевые внешние запросы:** никаких Google Fonts, внешних CDN, трекеров и сторонних скриптов. Используется выверенный системный стек шрифтов (`ui-monospace`, JetBrains Mono / SF Mono / Fira Code / Cascadia Mono fallback) + системный гротеск для длинного чтения.
- **SQLite в режиме WAL (`PRAGMA journal_mode = WAL; PRAGMA synchronous = NORMAL;`):** неблокирующее конкурентное чтение и мгновенные выборки по индексам.

## 3. Дизайн-система: тихий редакционный минимализм

Первая итерация была в эстетике измерительного прибора (шильдики, тикер,
координатные индексы секций). Она оказалась перегруженной: слишком много
деталей на единицу смысла. Действующая система — обратная по духу.

1. **Один акцент, много воздуха.** Фон, текст и одна волосяная линия. Акцент
   (`#c99a4d` в тёмной теме, `#9a5227` в светлой) используется только для
   ссылок, активного состояния и hover. Никаких рамок-панелей, теней,
   градиентов, скруглений больше 3 px и декоративных значков.
2. **Две темы, один документ.** OBSIDIAN (`#0b0b0c`) и PAPER (`#fbfaf7`) — два
   набора CSS-переменных; тема хранится в cookie `rz_theme` и рендерится
   сервером сразу, без вспышки.
3. **Типографика вместо графики.** Заголовки и текст статей — системный
   антиквенный шрифт (`Iowan Old Style / Palatino / Georgia`), интерфейс —
   системный гротеск, только код и числа — моноширинный. Ноль веб-шрифтов,
   ноль изображений, ноль иконок: единственный графический элемент страницы —
   сам текст.
4. **Ритм.** Одна колонка 680–880 px, отступы кратны 4 px и растут клампом
   (`clamp(48px, 9vw, 96px)`), разделители — только `border-top: 1px`.
   Список статей — строки с заголовком, аннотацией и тихой мета-строкой;
   никаких карточек, бейджей и счётчиков на публичной части.
5. **Что убрано намеренно:** тикер с телеметрией, спека узла, нумерация
   секций, индексы строк, счётчик просмотров в подвале, блоки-«шильдики» в
   кабинете. Метрики остались в кабинете (там они уместны) и в заголовке
   `Server-Timing` (там они не видны и не мешают).

## 4. Двуязычность (RU + EN)

- Интерфейс полностью локализован: словари `RU` и `EN` — статические структуры в `src/i18n.rs`, ни одной строки в шаблонах.
- Язык задаётся префиксом URL: `/` и `/articles/...` — русский, `/en` и `/en/articles/...` — английский. Это даёт корректные `hreflang`, канонические адреса и RSS-ленты на каждом языке.
- Каждая статья хранит `lang` и `translation_key`; перевод связывается по ключу, и страница статьи показывает ссылку «Читать на английском» / «Read in Russian», ведущую на тот же материал.

## 5. Личный кабинет владельца (`/cabinet`)

- Закрытый раздел **только для владельца сайта** (без публичной регистрации).
- Безопасность:
  - Пароль хранится исключительно в виде `PBKDF2-HMAC-SHA256` (210 000 итераций + 16-байтная криптостойкая соль OpenSSL `libcrypto`).
  - Сессии в SQLite с криптостойким 256-битным токеном (в БД хранится только SHA-256 хеш), cookie `HttpOnly; SameSite=Strict`, проверка `Origin`/`Referer`/`Sec-Fetch-Site` на всех мутирующих формах, одноразовый CSRF-токен на форме входа и rate-limiter: 6 попыток за 10 минут, затем 10 минут блокировки.
  - CSP с `default-src 'none'` и разрешением скрипта по SHA-256 хешу; Markdown экранируется полностью, ссылки допускаются только `http(s)`, `mailto`, относительные и `#anchor`.
- Возможности кабинета:
  - Управление статьями: создание, редактирование Markdown, черновики (`Draft`) и публикации (`Published`), закрепление (`Pinned`), теги, язык (`RU`/`EN`), описание (summary), чтение по минутам.
  - Редактирование профиля и манифеста сайта (имя, статус, био RU/EN, ссылки GitHub / Telegram / Email / Matrix) прямо из браузера.
  - Встроенная приватная телеметрия без сторонних счётчиков: просмотры за 14 дней, уникальные посетители (дневной хеш, без IP), доля ботов, топ-пути, среднее и p95 время рендера в микросекундах, средний размер ответа.
  - Смена пароля владельца и управление активными сессиями (выход на всех устройствах) + экспорт всех статей в JSON-бэкап одной кнопкой.

## 6. Лёгкость развертывания на VPS

- Нулевая зависимость от внешних СУБД (PostgreSQL/Redis не нужны) и рантаймов (Node/Python/Docker daemon не обязательны).
- В репозитории поставляются:
  - `Cargo.toml` с агрессивным профилем `[profile.release]` (`lto = true`, `codegen-units = 1`, `strip = true`, `opt-level = 3`);
  - `deploy/rudolfzinovev.service` — готовый hardened `systemd` unit;
  - `deploy/Caddyfile` и `deploy/nginx.conf` — конфигурации reverse-proxy с автоматическим TLS для `rudolfzinovev.me`;
  - `Dockerfile` и `docker-compose.yml` — опциональная одношаговая сборка в минимальный контейнер;
  - `deploy/install-vps.sh` — идемпотентный скрипт выкатки на чистый Debian/Ubuntu VPS (пакеты, сборка, пользователь `rz`, unit, Caddy, cron-бэкап).

## 8. Фактическое состояние реализации (v0.1.0)

Документ выше — нормативный. Ниже — что именно уже реализовано и чем это
проверяется, чтобы не расходиться с кодом.

### Компромиссы против первоначального плана

| Пункт плана | Как сделано сейчас | Почему |
|---|---|---|
| Автоопределение языка через `?lang=` и cookie `rz_lang` | Язык — это префикс URL (`/` и `/en`) | Канонические адреса, `hreflang`, две RSS-ленты, кэширование по URL; меньше состояний |
| Сайт по умолчанию русскоязычный | `detect_lang` смотрит `Accept-Language` только для `/login` (там нет префикса) | На публичных страницах язык однозначен из URL |
| Счётчик просмотров в подвале страницы | Счётчик пишется в БД и виден в кабинете | Байт-стабильный HTML → работающий `ETag`/`304` |
| «Приборная» эстетика первой итерации | Тихий редакционный минимализм | Слишком много деталей; текст важнее декора |
| Gzip ассетов «при старте» | Gzip на лету в `finalize_response` | 32 КБ CSS сжимаются за десятки микросекунд, память не занята |
| `Pinned` | `featured` (флаг «избранное»), сортировка в начале ленты | То же поведение, одно поле |
| `include_bytes!` для статики | `include_str!` для CSS/JS (UTF-8) | Нет лишнего копирования в `String` для SVG-фавикона |

### Что покрыто тестами

`cargo test` — 25 тестов, среди них:

- `http::tests` — url-decode, нормализация путей (включая кириллицу), rate
  limiter, детект ботов;
- `sqlite`/`db::tests` — сиды 4 пар RU/EN, фильтры по языку/тегу/поиску,
  аутентификация владельца, сессии и их отзыв, профиль, JSON-бэкап,
  агрегаты телеметрии (avg/p95/уникальные);
- `markdown::tests` — заголовки с якорями и TOC, экранирование `<script>`;
- `templates::tests` — главная, статья с XSS-заголовком, RSS, переключение
  языковых путей;
- `app::tests` — публичные маршруты RU/EN, 404, редирект `/cabinet` → `/login`,
  полный вход (CSRF-cookie → POST → сессия), отказ мутации без `Origin`
  и успех с ним, отсутствие плейсхолдеров рендера в HTML, а также полный
  цикл кабинета: создание черновика → публикация → удаление (регрессия на
  случай, когда ответ POST-ветки терялся в роутере).
