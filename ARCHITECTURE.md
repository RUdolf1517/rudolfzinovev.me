# ARCHITECTURE & ENGINEERING MANIFESTO — `rudolfzinovev.me`

Этот документ фиксирует неизменяемые архитектурные и продуктовые принципы репозитория **rudolfzinovev.me**. Любые последующие коммиты, PR и доработки обязаны строго им следовать.

---

## 1. Rust-First & Крайний минимум JS/TS (Hard Rule)

1. **Язык проекта — Rust.**
   - Весь HTTP-сервер, маршрутизация, рендеринг HTML (SSR), компиляция Markdown, работа с БД (SQLite), криптография/аутентификация, RSS, сжатие (gzip) и кэширование реализованы **исключительно на Rust**.
2. **Запрет на JS/TS-экосистему на клиенте и в сборке:**
   - Никаких `package.json`, `node_modules`, Webpack, Vite, Rollup, Babel, Tailwind CLI на клиенте.
   - Никаких SPA/гидратации (React, Next.js, Vue, Svelte, Astro, HTMX-зависимостей из CDN).
3. **Политика «Крайний минимум JS» (`<= 2 KB` сжатого vanilla JS, Progressive Enhancement):**
   - **100% функционала сайта** (чтение статей, фильтрация по тегам, поиск, переключение языка `RU/EN`, вход в личный кабинет, создание/редактирование/удаление статей и настроек профиля) **обязано работать вообще без JavaScript** (через чистый серверный HTML, HTTP POST/GET, формы и cookies).
   - Единственный клиентский файл `assets/app.js` подключается с атрибутом `defer`, не имеет внешних зависимостей и отвечает **только за микро-улучшения UX**:
     - хоткеи терминальной навигации (`/`, `g h`, `g a`, `g c`) и копирование блоков кода в один клик;
     - живой предпросмотр и подсчёт символов в редакторе статей владельца + защита от случайного закрытия несохранённого черновика.

## 2. Производительность при загрузке (Zero-Bloat Optimization)

Цель сайта — мгновенный First Contentful Paint (суб-миллисекундный ответ сервера, первый экран в пределах одного TCP initial congestion window ~14 KB):

- **Single Self-Contained Binary:** статика (`assets/style.css`, `assets/app.js`, SVG favicon) вшита в бинарник через `include_str!` на этапе компиляции. На диске VPS лежит **один исполняемый файл** и файл базы данных SQLite.
- **Встроенное Gzip-сжатие и версионирование статики:** любой `text/*` ответ (включая HTML и CSS) сжимается на лету через `libz` (`deflateInit2_`, уровень 6) при `Accept-Encoding: gzip`. Статика отдаётся с `Cache-Control: public, max-age=31536000, immutable` и ETag по SHA-256 содержимого.
- **Байт-стабильный HTML:** страница не содержит меняющихся счётчиков. Время рендера уходит в заголовок `Server-Timing` и в микро-скрипт, CSP задаётся хешем скрипта (`script-src 'sha256-…'`) вместо nonce. Поэтому `ETag` + `If-None-Match` реально дают `304` без тела.
- **Нулевые внешние запросы:** никаких Google Fonts, внешних CDN, трекеров и сторонних скриптов. Используется выверенный системный стек шрифтов (`ui-monospace`, JetBrains Mono / SF Mono / Fira Code / Cascadia Mono fallback) + системный гротеск для длинного чтения.
- **SQLite в режиме WAL (`PRAGMA journal_mode = WAL; PRAGMA synchronous = NORMAL;`):** неблокирующее конкурентное чтение и мгновенные выборки по индексам.

## 2a. Данные: одна таблица, два типа записей

Заметки и проекты живут в одной таблице `articles` с колонкой `kind`
(`note` | `project`). Причина: у них одинаковые поля, один редактор, один
механизм переводов (`translation_key`), один поиск и одна телеметрия.
Различие — только в том, какой раздел сайта их показывает и каким словом
подписан каталожный номер.

- `Kind` в `models` — единственный источник правды о коде и сегменте URL;
- адреса: `/notes/:slug`, `/projects/:slug` (+ `/en`), тип в URL обязан
  совпадать с `kind`, иначе 404;
- старые адреса `/articles…` отвечают `303` на новые;
- для существующих баз колонка добавляется на старте
  (`migrate_kind`), все старые строки получают `note`.

## 2b. Транспорт: axum, и только он

HTTP-слой — `axum 0.8` на `tokio`. Своего HTTP-сервера больше нет: он занимал
616 строк (`src/http.rs` + `src/app.rs`) и требовал внимания при каждой правке
заголовков, keep-alive или разбора тела. Удалён целиком.

Ядро не тронуто и по-прежнему не тянет крейтов: `sqlite`, `crypto`, `db`,
`models`, `i18n`, `markdown`, `templates`, `json`, `github` — свой код.
Зависимости ровно две прямые: `axum` и `tokio`; `serde`/`serde_json` не нужны,
потому что JSON пишет и читает `src/json.rs`, а единственный документ, который
сайт отдаёт (бэкап кабинета), собирается вручную в `db.rs`.

Что перенесено один в один, потому что это правила, а не транспорт:

- язык как префикс URL (`/`, `/en`), канонические адреса;
- CSRF: `Origin`/`Referer` + `Sec-Fetch-Site` на каждом POST, плюс одноразовый
  токен на форме входа;
- сессии в cookie `HttpOnly; SameSite=Strict`, в базе — только SHA-256 токена;
- лимитеры: 6 попыток входа / 10 минут, 240 записей / минуту;
- CSP с хэшем скрипта, `X-Content-Type-Options`, `Referrer-Policy`,
  `frame-ancestors 'none'`;
- `ETag`/`304` по несжатому телу, gzip для текстовых типов;
- `Server-Timing` с реальным временем рендера;
- телеметрия: только GET публичных страниц, реферер урезан до хоста.

Что меняется по существу: вместо своего пула потоков — tokio multi-thread,
вместо разбора сокета — hyper, вместо ручного роутинга — таблица маршрутов
axum (`/notes/{slug}`). `--workers` по-прежнему задаёт размер пула потоков
рантайма. Адрес клиента для лимитеров и уникальных посетителей считает
middleware `peer_ip` в `src/main.rs` (`X-Forwarded-For`, иначе адрес сокета
через `ConnectInfo`) и кладёт его в приватный заголовок, чтобы обработчики
не гадали.

## 2c. GitHub и журнал проекта: две истории, которые нельзя смешивать

У проекта два независимых источника истории, и они намеренно не сводятся
в один список.

| | Автоматическая история | Журнал автора |
|---|---|---|
| Источник | GitHub REST API | владелец, вручную |
| Что содержит | релизы, коммиты, дату правки README | наблюдения, решения, этапы |
| Типографика | моно, дата слева, без орнамента | сериф, буквица, метка на поле |
| Хранение | `project_events` (кэш) | `project_notes` |
| Правка | невозможна | единственное, что правится |

Смешивать их нельзя: автоматическая лента отвечает на вопрос «что
произошло в коде», журнал — «почему так решили». Общий список превратил бы
второе в комментарии к первому.

### Привязка

`project_repos` — одна строка на проект: `repo` в виде `owner/name` плюс
кэш фактов (звёзды, форки, язык, лицензия, последний релиз, дата последнего
пуша, `fetched_at`, `last_error`). Привязка задаётся в кабинете
(`/cabinet/projects/<id>`) строкой `owner/name` или ссылкой на GitHub;
`normalise_repo` принимает `https://github.com/…` и `.git`, но отвергает
всё, что не ровно два сегмента безопасных символов.

### Обновление

- страница проекта никогда не ждёт сеть: она показывает кэш, а обновление
  запускается, только если `fetched_at` старше 30 минут
  (`github::refresh_due`);
- в кабинете есть кнопка «Refresh now» — она ходит в API синхронно и
  показывает результат;
- любая ошибка (`network`, `not-found`, `rate-limited`, `api-error`)
  записывается в `last_error`, **старый снимок остаётся**; публичная
  страница честно пишет «GitHub сейчас недоступен — показан последний
  снимок»;
- перепривязка к другому репозиторию стирает ленту старого — иначе факты
  одного проекта висели бы под именем другого.

### Что именно тянется

`/repos/:repo` — факты; `/releases/latest` — последний релиз;
`/commits?sha=:branch&per_page=20` — коммиты; `/commits?path=README.md&per_page=1`
— дата правки README. Issues и Pull Requests по умолчанию **выключены**:
это отдельный флаг `show_issues`, и включённый показывает только счётчик
открытых issues, без списка.

### Сеть: libssl напрямую (без HTTP-крейтов)

`src/github.rs` говорит по HTTPS через `TcpStream` + libssl (те же системные
линки, что и `libcrypto`): SNI, `SSL_VERIFY_PEER` с системными корнями,
`SSL_get_verify_result`, разбор `Content-Length` и `Transfer-Encoding:
chunked`. JSON разбирает свой парсер `src/json.rs` (объекты, массивы,
суррогатные пары, числа) — serde не тянем принципиально. Диагностика:
`rudolfzinovev github owner/name` печатает то, что попадёт в кэш, не
запуская сервер.

### Журнал

`project_notes`: `project_id`, `lang`, `kind` (`note` | `decision` |
`milestone`), `title`, `body_md`, `log_date`, `public`. Три типа
различаются меткой на поле (`N` / `D` / `M`) и подписью словами. `public =
0` — черновик: посетитель его не получает вовсе (фильтр в SQL, не в
шаблоне), владелец видит с пометкой. Заметка журнала принадлежит проекту из
URL, а не тому, что пришло в форме.

## 3. Дизайн-система: архив, который читается как книга

Принцип: **индивидуальность берётся из структуры, а не из цвета.** Два
предыдущих подхода — приборная панель и чистый минимализм — были отклонены:
первый утопил контент в декоре, второй оказался неотличим от любого
инди-блога. Текущая система добавляет к минимализму аппарат печатного
издания: нумерацию, выноски, поля.

1. **Колонтитул, не навигация.** `.run` — одна строка: марка, имя, разделы,
   инструменты. Активный раздел помечен `aria-current`, а не цветной плашкой.
2. **Номера вместо счётчиков.** `templates::catalogue_no(id)` — каталожный
   номер записи («01»). Он же стоит в шапке статьи и в подвале рядом со
   счётчиком слов — так страница читается как страница книги.
3. **Два уровня каталога.** Номер записи отвечает на «которая по счёту»,
   год (`templates::ledger`) — на «когда»; между годами стоит линейка.
4. **Поле как вторая колонка.** Статья — grid `33em + 1fr` от 1180 px:
   текст слева, оглавление и заметки справа, ничего не отнимая у прозы.
5. **Точечные выноски.** `.entry-line` — flex из четырёх частей
   (`entry-no` · `entry-title` · `entry-dots` · `entry-date`); выноска —
   `border-bottom: 1px dotted` на пустом спане, дата прижата вправо. Номер
   сидит в фиксированной колонке `3.4ch`, поэтому трёхзначные номера не
   разъезжают строку, а подстроки выровнены по `--ledger-indent`.
6. **Поля для заметок.** `> [!note]` в Markdown рендерится в
   `<span class="note">`; от 1180 px он уезжает в правое поле
   (`--margin-note: 190px`), ниже — остаётся в потоке. Никакого JS.
7. **Одна антиква, один акцент.** Текст — `--serif`, метаданные и номера —
   `--mono`. Акцент (`#8b4a1c`) только на ссылках, активном состоянии и
   каталожном номере главы.
8. **Одна тёплая подложка.** Тёмной темы нет: переключатель удваивает работу
   над каждой страницей и всегда оставляет один из режимов недоработанным.
   Вместо двух схем — единственный фон `--paper: #fcfbf7`: почти белый, с едва заметной желтизной,
   бумага вместо белого. Без текстур, теней и второго слоя — фон не должен
   спорить с текстом.

Ширины: `--text: 720px` для прозы, `--page: 960px` для оболочки,
`--margin-note: 230px` для поля. Никаких карточек, теней, скруглений и
иконок на публичной части; кабинет использует те же переменные, но с
таблицами и панелями.

## 4. Двуязычность (RU + EN)

- Интерфейс полностью локализован: словари `RU` и `EN` — статические структуры в `src/i18n.rs`, ни одной строки в шаблонах.
- Язык задаётся префиксом URL: `/` и `/articles/...` — русский, `/en` и `/en/articles/...` — английский. Это даёт корректные `hreflang`, канонические адреса и RSS-ленты на каждом языке.
- Каждая статья хранит `lang` и `translation_key`; перевод связывается по ключу, и страница статьи показывает ссылку «Читать на английском» / «Read in Russian», ведущую на тот же материал.

## 5. Личный кабинет владельца (`/cabinet`)

- Закрытый раздел **только для владельца сайта** (без публичной регистрации).
- Безопасность:
  - Пароль хранится исключительно в виде `PBKDF2-HMAC-SHA256` (210 000 итераций + 16-байтная криптостойкая соль OpenSSL `libcrypto`).
  - Сессии в SQLite с криптостойким 256-битным токеном (в БД хранится только SHA-256 хеш), cookie `HttpOnly; SameSite=Strict`, проверка `Origin`/`Referer`/`Sec-Fetch-Site` на всех мутирующих формах, одноразовый CSRF-токен на форме входа и rate-limiter: 6 попыток за 10 минут, затем 10 минут блокировки.
  - CSP с `default-src 'none'` и разрешением скрипта по SHA-256 хешу; Markdown экранируется полностью, ссылки допускаются только `http(s)`, `mailto`, относительные и `#anchor`.
- Возможности кабинета:
  - Управление статьями: создание, редактирование Markdown, черновики (`Draft`) и публикации (`Published`), закрепление (`Pinned`), теги, язык (`RU`/`EN`), описание (summary), чтение по минутам.
  - Редактирование профиля и манифеста сайта (имя, статус, био RU/EN, ссылки GitHub / Telegram / Email / Matrix) прямо из браузера.
  - Встроенная приватная телеметрия без сторонних счётчиков: просмотры за 14 дней, уникальные посетители (дневной хеш, без IP), доля ботов, топ-пути, среднее и p95 время рендера в микросекундах, средний размер ответа.
  - Смена пароля владельца и управление активными сессиями (выход на всех устройствах) + экспорт всех статей в JSON-бэкап одной кнопкой.

## 6. Лёгкость развертывания на VPS

- Нулевая зависимость от внешних СУБД (PostgreSQL/Redis не нужны) и рантаймов (Node/Python/Docker daemon не обязательны).
- В репозитории поставляются:
  - `Cargo.toml` с агрессивным профилем `[profile.release]` (`lto = true`, `codegen-units = 1`, `strip = true`, `opt-level = 3`);
  - `deploy/rudolfzinovev.service` — готовый hardened `systemd` unit;
  - `deploy/Caddyfile` и `deploy/nginx.conf` — конфигурации reverse-proxy с автоматическим TLS для `rudolfzinovev.me`;
  - `Dockerfile` и `docker-compose.yml` — опциональная одношаговая сборка в минимальный контейнер;
  - `deploy/install-vps.sh` — идемпотентный скрипт выкатки на чистый Debian/Ubuntu VPS (пакеты, сборка, пользователь `rz`, unit, Caddy, cron-бэкап).

## 8. Фактическое состояние реализации (v0.1.0)

Документ выше — нормативный. Ниже — что именно уже реализовано и чем это
проверяется, чтобы не расходиться с кодом.

### Компромиссы против первоначального плана

| Пункт плана | Как сделано сейчас | Почему |
|---|---|---|
| Автоопределение языка через `?lang=` и cookie `rz_lang` | Язык — это префикс URL (`/` и `/en`) | Канонические адреса, `hreflang`, две RSS-ленты, кэширование по URL; меньше состояний |
| Сайт по умолчанию русскоязычный | `detect_lang` смотрит `Accept-Language` только для `/login` (там нет префикса) | На публичных страницах язык однозначен из URL |
| Счётчик просмотров в подвале страницы | Счётчик пишется в БД и виден в кабинете | Байт-стабильный HTML → работающий `ETag`/`304` |
| «Приборная» эстетика первой итерации | Архив, который читается как книга | Декор утопил текст; чистый минимализм оказался неотличим от любого блога — индивидуальность даёт аппарат издания |
| Gzip ассетов «при старте» | Gzip на лету в `finalize_response` | 32 КБ CSS сжимаются за десятки микросекунд, память не занята |
| `Pinned` | `featured` (флаг «избранное»), сортировка в начале ленты | То же поведение, одно поле |
| `include_bytes!` для статики | `include_str!` для CSS/JS (UTF-8) | Нет лишнего копирования в `String` для SVG-фавикона |

- `github::tests` — разбор HTTP-ответа с `Content-Length` и chunked, 404/403,

- `handlers::http_tests` — публичные страницы RU/EN отдают 200 и документ,

  редиректит на `/login` (303), а мутации без сессии получают 401, включая
  привязку репозитория и создание заметки журнала; страница проекта с
  привязанным репозиторием рендерит блок GitHub и блок журнала.
